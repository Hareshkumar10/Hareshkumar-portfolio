Academic project · CIS6003 Advanced Programming

A completed academic Java desktop application covering patient records, appointments, clinical notes, billing, staff accounts, and clinic reports.

Languages & libraries

Java 21, Swing for desktop screens, SQL and MySQL for persistence, MySQL Connector/J (JDBC) for database access, jBCrypt for password hashing, NetBeans AbsoluteLayout for forms, and JUnit for tests. A small Java HTTP/JSON service provides appointment lookup.

Development & testing tools

Apache NetBeans 25, Apache Ant, MySQL Server and Workbench, Git, and GitHub. The GitHub Actions workflow prepares a MySQL test database, runs tests, and builds the application with Ant.

Clinic workflow

  1. A staff member signs in; requested accounts require administrator approval and role-based access controls available actions.
  2. Register or find a patient, check dentist availability, and book or reschedule an appointment.
  3. Record clinical findings, treatment notes, and the treatment provided.
  4. Create an invoice, record payment, and produce a receipt.
  5. Review reports and audit history; administrators manage staff and clinic settings.

Architecture & source structure

Swing screens → service-layer rules → data access objects (DAOs) → MySQL. The appointment lookup API also calls the service layer.

  • src/ — Java classes, NetBeans forms, models, services, DAOs, and HTTP service.
  • database/ — schema, sample records, and database checks.
  • test/ — service integration, validation, access-control, and export tests.
  • config/application.properties — optional local database settings (not committed); lib/ — supporting libraries.
  • build.xml — clean, test, and JAR packaging tasks.

Business website · Catalogue prototype

A multilingual jewellery catalogue prototype for English, Tamil, and Sinhala visitors. Product content, photography, pricing, and translations require owner review before launch.

Languages & frameworks

TypeScript, React, Vinext, HTML and CSS with Tailwind CSS. API routes use prepared SQL statements directly against Cloudflare D1 (SQLite). Drizzle defines the schema and supports migration tooling; the server targets Cloudflare Workers.

Development & quality tools

Node.js, npm, Vite, Wrangler, and Drizzle Kit for database migrations. The project includes Node-based validation tests, HTTP integration checks, and production build tasks.

Visitor & administrator workflow

  1. Visitors choose a language, browse published products, and open an item to inspect material, price, and availability.
  2. A product enquiry opens WhatsApp with item details. The catalogue supports price-on-enquiry items and does not process checkout or payments.
  3. An authorised administrator creates or edits products, assigns a unique item number, and controls draft or published status.
  4. The administrator updates stock and 22K / 24K gold rates in LKR; rates older than 24 hours are marked as stale.

Architecture & source structure

React storefront / admin interface → server API and validation → prepared SQL queries → D1 database. Admin access is checked server-side against an allowlist using the hosting identity integration.

  • app/storefront.tsx — catalogue navigation and product details.
  • app/admin/ — protected product and gold-rate editor.
  • app/api/ — public catalogue reads and administrator updates.
  • lib/content.ts — translations, LKR formatting, and WhatsApp enquiry text.
  • lib/auth.ts and lib/validation.ts — access and input checks.
  • db/queries.ts — D1 access and shared query columns; db/schema.ts / drizzle/ — schema and migrations; tests/ — validation and HTTP checks.

Data safeguards

Prepared database queries, unique item-number constraints, same-origin checks for changes, and version checks to prevent overwriting another administrator’s edits.

Visitor workflow
